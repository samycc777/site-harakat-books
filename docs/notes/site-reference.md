# site-harakat-books — reference

Rules are in ../../CLAUDE.md; this file is the long reference.

## Two looks (`public/site.css`, `public/theme.js`)
- Everyone: «paper» look (Zaid's request): like the المقالات الواضحات videos: white page in a pink-and-red double frame on black, Amiri text (OFL), Thuluth Decorated titles (fontstatic.com, licence not stated), red accents; dark = cream on navy. CSS rules under `:root:not([data-look=classic])` at the end of site.css.
- Home page order: title, «بماذا يبدأ…», one row with «حسب المؤلف/العلم» + harakat filter (`.controls`), sticky search box, «متابعة القراءة», recent lists, author buttons, sections. List PDF buttons are outlined (`.book .btn`), solid only on hover; page count joined to «صفحة» by a no-break space. Author buttons: tighter chips; on phones a 4-row strip that scrolls sideways. Author/subject sections use `content-visibility:auto` (sync.py writes `--n` = book count for the size estimate; the SEARCH script re-scrolls `#id` jumps for a few frames so they land right).
- Colours (everyone, both looks): the moon button opens nine circles (light, dark, green, night blue, black, dark green, Next.js: black with thin grey lines, Gruvbox, charcoal gold); `theme.js` sets `data-theme=dark` for dark ones and `data-palette` for the extra ones (localStorage `theme` + `palette`); CSS at the end of site.css, one rule per look.
- Bilal only: the older «classic» look (cream, brown, Droid Arabic Naskh). Any page opened with `?look=classic` remembers it in that browser; `?look=paper` undoes it. Keep both working when changing the look.
- Fonts in `public/fonts/` are woff2 subsets (pyftsubset, Arabic + Latin). Made smaller by `~/dev/tool-zaid-sites-kit/fonts/shrink.py` (originals in `fonts-src/`; `*-rare.woff2` = letters no page shows, fetched only if one appears; rerun it after adding a font). Pages preload Amiri and carry an empty icon link (without it browsers fetched the whole home page as `/favicon.ico`). Never use Adwa Assalaf here: paid font.

## Where things live
- `books.json` — published list (the tafsirs: one entry per PDF volume, `html` = media-harakat-books `pdf/<name>.html` from their `build_pdf.py` with `KEEP_HTML=1`, used for the reading page): `authors` (display order, with «الشيخ») `author_slugs` (author → folder of the author's page; missing = `a<n>`) and `books` (slug, title, author, pdf file name in media-harakat-books/pdf/, optional `source` = list of original URLs, optional `kind` = book|article|fatwa when sync.py's guess is wrong).
- `coming.json` — «قريبًا» section at the end of the home page (Bilal's order): requested books (title, author; hidden by sync.py once a book with that title is live) and authors without chosen titles (chips). Hand-edited; remove an author once their books are live.
- Harakat filter (home page, and author pages that have both kinds): books.json `"harakat": false` → `li.book.nh`; sync.py `FILTER` + the `SEARCH` script hide books, empty groups and chips and recount; choice remembered in localStorage `harakat`.
- «أُضيفت حديثًا» / «شُكِّلت حديثًا» (home page, above the author buttons, Bilal's order): books added / whose `"harakat": false` was removed on the viewer's today only; clicking a title folds its list (`<details>`, state in localStorage `fold-<id>`). sync.py `recent_times()` reads the dates from git history of books.json (last 2 days; uncommitted changes = now); the page's `RECENT` script drops other days when viewed, so no extra file to keep.
- `reading.json` — «بماذا يبدأ طالب العلم؟» page `/ibtida/` (button on the home page; sync.py `start_page()`): per shaykh, his own words on beginners' books (verbatim, with source URL) and the books in his order, grouped by science; `slug` = book on the site, else `title` (+`author`, `href` = author page) shown greyed. Only what the shaykh said: no books or order of our own.
- `sciences.json` — subject of each book (`order` = display order, `books` = slug → subject; Zaid may send corrections): the home page's «حسب العلم» view (buttons in sync.py `VIEWS`, choice remembered by `theme.js`, CSS `.views`/`.v-author`/`.v-science`). A book missing there shows under «أخرى» and sync.py warns.
- `groups.json` (Zaid's order): books listed there show under their group's heading (one per person Shaykh Rabi refuted in several works, and the chapters of his commentary on al-Ajurri's «الشريعة») after the kind groups, with jump chips on the author page; only titles that name the person were grouped.
- Under each author, books are grouped by kind (sync.py `kind()`): rabee.net/book PDFs, Shamela, printed scans, tafsirs = «كتب»; other rabee.net posts and Facebook posts = «مقالات»; rabee.net fatwas/benefits or a «فتاوى» title = «فتاوى وفوائد».
- `scripts/sync.py` — copies the listed PDFs from `~/dev/media-harakat-books/pdf/` (read-only) to `public/pdf/<slug>.pdf` and regenerates `public/index.html` (needs `pypdf`). Every book needs a source link: `source` in books.json, else the URLs in media-harakat-books `books/<slug>/src/sources.tsv` (rabee.net books); sync.py stops if neither.
- `public/` — the deployed folder. `site.css`, `theme.js`, `account.js`, `notes.js`, `exercises.js`, `progress.js`, `toc.js`, `reader.js`, and `report.js` are hand-edited; `index.html`, `<slug>/index.html`, the author pages and `pdf/` are written by sync.py (which appends `?v=<hash>` cache-busters to static CSS/JS links): never edit them by hand.
- `public/exercises.js` (hand-edited, loaded on books with `"exercises": true` in `books.json`, before `progress.js`): turns «تمارين» / «تمرين» sections into interactive controls (blanks, editable table cells, ✓/× toggles, multiple-choice chips, click-to-underline/circle, vowelization box, open i'rab boxes) with a floating harakat helper bar; saves in localStorage `ex:<slug>` and syncs per-field to D1 (`functions/api/exercises.js`, table `exercises`) when signed in.
- Home page «حسب العلم» view: `index.html` keeps `.v-science` section shells + compact `#sci-data` JSON and clones book items from `.v-author` lazily on first switch to science view (halving `index.html` size and initial DOM). Search matches both title and author name, debounces input, supports `/` to focus and `×`/Esc to clear, and filters nav chips to matching authors/sciences.
- `public/notes.js` (hand-edited, CSS in site.css): on every book page, footnote numbers become buttons that open the note in a pop-up; runs immediately when loaded with `defer` (before `progress.js`) so removed `.fn` blocks never shift restored scroll; notes it cannot pair (lettered lists, «(*)», «(١، ٢)») stay printed under the page.
- `public/reader.js` (hand-edited, on book pages): font-size controls (`أ+` / `أ−`, saved in localStorage `fs` and applied pre-paint by `theme.js`), harakat-insensitive in-book search bar (`#findbar`, `/` shortcut, floating `#findbtn`), short passage deep links (`#p<n>` / `#p<start>-<end>`, 1-based over direct `p`/`h2`/`h3` in `article.text`, highlighted with `.hl`), and clean `@media print` styling in `site.css`.
- Navigation aids: a «أُضيفت حديثًا» / «شُكِّلت حديثًا» list with more than 6 books starts folded unless the reader opened it (RECENT script); author pages with more than one kind get jump chips to `#k-book` / `#k-article` / `#k-fatwa` (`nav.authors.kinds`, counts kept by SEARCH); `#fab` holds bottom-left floating buttons (`#tocbtn`, `#findbtn`, `#totop`); `public/toc.js` (hand-edited) on book pages with 3+ `.text h2` opens the book's own headings, current one marked, jumps without changing `#`.
- `public/progress.js` (hand-edited): book pages remember the reading place (paragraph + how far in) and how far through the book, through `account.js`, and scroll back to it on reopening; a thin bar at the top of the screen shows how far. Not on a `#…` link; back at the title forgets the place (a finished book stays finished).
- `public/account.js` (hand-edited, on every page; CSS «reader account» at the end of site.css): progress of every book in localStorage `reading` (`{slug: {s, p, d, t}}`; old `place-<slug>` keys are moved into it); bar + «٪» under each started book on the lists; «متابعة القراءة» on the home page (6 last unfinished books); round ↑ button on long lists; account button next to the moon.
- Sign in with Google (Bilal's order): `functions/api/auth.js` checks Google's ID token and sets an HttpOnly cookie `ks` signed with the Pages secret `SESSION_SECRET`; `functions/api/progress.js` keeps each reader's progress as one JSON row in D1 `kutub-mashkulah-readers` (binding `DB`, set on the Pages project through the API, not a wrangler file; table made on first use, `scripts/progress-schema.sql`). Newest time wins per book; synced on every page load and 15 s after reading moves. Only Google's account number, name and picture URL are kept (in the cookie, not the database).
- `public/privacy/index.html` (hand-made, Bilal's order): privacy page Google requires for sign-in; linked from nowhere on the site (only from Google's sign-in settings), noindex; its «حذف بياناتي» button calls DELETE `/api/progress`, then signs out. Keep it true if what is stored changes.
- The account button stays hidden until the Pages variable `GOOGLE_CLIENT_ID` (Google Cloud project `kutub-mashkulah` of samycc777@gmail.com → Google Auth Platform → client «kutub-mashkulah site», origins https://kutub-mashkulah.pages.dev and http://localhost:8788; set, published) exists; without it everything else works from the browser alone. Local test: `.dev.vars` (GOOGLE_CLIENT_ID, SESSION_SECRET) + `wrangler pages dev public --d1 DB=local-db`.
- `scripts/years.py` (called by sync.py): on the website only, years (with هـ/م, after سَنَة/عَام/a month/«ت») are written in vowelled words, printed digits after them in brackets: «عَامِ أَلْفٍ وَأَرْبَعِمِائَةٍ وَسَبْعَةٍ وَعِشْرِينَ (١٤٢٧)». Dates with slashes/dashes stay digits. `python3 scripts/years.py` prints samples.
- Book page text comes from media-harakat-books `books/<slug>/index.html` (its build.py output), so rebuild the book there before syncing after a text fix.

## Search engines
- sync.py writes into every page's `<head>`: canonical URL, description and og tags (book title, author, the book's own subtitle, harakat stripped because people search without them; no text of ours), schema.org Book data on book pages; plus `public/sitemap.xml` and `public/robots.txt`. Tab title: «<title> — <author> | كتب مشكولة».
- Bing/Yandex: `scripts/indexnow.py` (key file `public/<key>.txt`); deploy.yml sends the changed pages after each push; `indexnow.py all` sends every page. Google reads the sitemap (Search Console, Bilal's Google account).

## «إبلاغ عن خطأ» (reader reports)
- Button + box under each book's text (`REPORT` in sync.py, `public/report.js`): it posts to `functions/api/report.js` (Pages Function), which opens an issue «[بلاغ] <title>» in this repo; `report.yml` then comments @samycc777 so GitHub emails Bilal (own-token issues send no notice).
- The button shows only when the Pages secret `GITHUB_TOKEN` exists (fine-grained token: this repo only, Issues read/write). Set/renew: `bash scripts/set-report-token.sh` (asks for the token, saves it, redeploys).
- Fix reports: `gh issue list -R samycc777/site-harakat-books --search "[بلاغ] in:title"`; fix the text in media-harakat-books, rebuild, sync here, close the issue.
